# نظام التواصل الداخلي ولوحة إدارة هُدى

## الدخول الأول

تحتوي قاعدة SQLite على حساب إدارة واحد فقط. عند إنشاء قاعدة البيانات لأول مرة، يُضاف تجزئة bcrypt لكلمة المرور الأولية التي حُددت أثناء إعداد المشروع؛ لا تُحفظ كلمة المرور كنص صريح ولا تُرسل إلى الواجهة. بعد أول دخول، غيّرها من قسم **تغيير كلمة المرور**.

إذا كانت قاعدة البيانات موجودة مسبقاً، تضيف عملية التهيئة الجداول الجديدة دون حذف بيانات المستخدمين أو التقدم أو الجلسات.

## التخزين

- الرسائل والردود والمرفقات الوصفية وحساب الإدارة تُخزَّن في قاعدة SQLite الحالية.
- تُحفظ ملفات الصور في مجلد `contact-uploads` بجوار ملف قاعدة البيانات المحدد في `DB_PATH`. لذلك يجب أن يكون المجلد على القرص الدائم نفسه المستخدم لقاعدة البيانات في بيئة الإنتاج.
- أنواع الصور المسموحة: PNG وJPEG وWEBP. الحد الأعلى خمس صور، 5 ميجابايت للصورة، و10 ميجابايت إجمالاً.
- لا يُقدّم مجلد الصور كملفات عامة؛ تُعرض الصور عبر مسار API محمي بجلسة الإدارة.

## مسارات API

- `POST /api/feedback/message` إرسال رسالة داخلية ومرفقاتها.
- `POST /api/feedback/admin/login` تسجيل دخول الإدارة بكلمة المرور فقط.
- `GET /api/feedback/admin/session` التحقق من جلسة الإدارة.
- `POST /api/feedback/admin/logout` إنهاء جلسة الإدارة.
- `GET /api/feedback/admin/messages` قائمة الرسائل.
- `GET /api/feedback/admin/messages/:id` تفاصيل الرسالة والردود والمرفقات.
- `POST /api/feedback/admin/messages/:id/replies` حفظ رد داخلي.
- `PATCH /api/feedback/admin/messages/:id/status` تحديث الحالة.
- `DELETE /api/feedback/admin/messages/:id` حذف الرسالة ومرفقاتها وردودها.
- `GET /api/feedback/admin/attachments/:id` عرض مرفق بعد التحقق من الإدارة.
- `POST /api/feedback/admin/password` تغيير كلمة مرور الإدارة بعد التحقق من الحالية.

جميع مسارات الإدارة، باستثناء مسار تسجيل الدخول، تتطلب جلسة إدارة صالحة. كما تُطبق حماية تحديد معدل محاولات تسجيل الدخول.

## ملاحظة البريد

تم إلغاء إرسال نموذج التواصل والردود إلى البريد. بقيت خدمة البريد العامة كما هي لأنها ما زالت مستخدمة في وظائف أخرى، مثل استعادة كلمة مرور حسابات المستخدمين.
