# هُدى — النسخة الاحترافية (Frontend + Backend حقيقي)

هذه نسخة مطوّرة من موقع "هُدى" الأصلي، بعد إضافة باك-إند حقيقي (Node.js + Express + SQLite)
بدل الاعتماد على `localStorage` بالمتصفح فقط.

## ما الذي تغيّر عن النسخة الأصلية؟

| الميزة | النسخة الأصلية | النسخة الحالية |
|---|---|---|
| تسجيل الدخول | localStorage + SHA-256 بالمتصفح | جلسات حقيقية (express-session) + تشفير bcrypt |
| بيانات المستخدم | تُفقد عند مسح المتصفح | محفوظة بقاعدة بيانات SQLite |
| تقدم التسبيح والأذكار | محفوظ محلياً فقط | محفوظ بالخادم، متاح من أي جهاز |
| آخر سورة تمت قراءتها | غير محفوظة | محفوظة تلقائياً وتُستعاد عند الدخول |
| حماية الصفحات | فحص محلي بسيط | فحص جلسة فعلي عبر API، والمسارات المحمية بالخادم ترفض الطلبات غير المصرّح بها (401) |

## التشغيل محلياً

```bash
cd backend
npm install
cp .env.example .env
# (اختياري) عدّل SESSION_SECRET بـ backend/.env

npm start
```

بعدها افتح المتصفح على:

```
http://localhost:3000/index.html
```

قاعدة البيانات (SQLite) تُنشأ تلقائياً كملف `backend/data/huda.db` عند أول تشغيل — لا حاجة لتثبيت أو تهيئة خادم قاعدة بيانات منفصل.

## بنية المشروع

```
huda-app/
├── netlify.toml                      ← إعدادات نشر الفرونت اند على Netlify
├── frontend/                         ← كل شيء يُنشر على Netlify (ولا شيء غيره)
│   └── index.html, css/, js/, pages/, assets/
└── backend/                          ← يُنشر على منصة منفصلة (Render مثلاً)، ليس على Netlify
    ├── server.js                     ← نقطة الدخول الرئيسية (Express)
    ├── db.js                         ← اتصال قاعدة البيانات ومخطط الجداول
    ├── routes/
    │   ├── auth.js                   ← تسجيل / دخول / خروج / الجلسة الحالية
    │   ├── progress.js               ← حفظ واسترجاع تقدم التسبيح والقراءة
    │   ├── memorization.js           ← تتبع الحفظ والمراجعة المتباعدة
    │   └── stats.js                  ← الإحصائيات المجمّعة
    ├── package.json
    └── .env.example
```

راجع **NETLIFY_DEPLOY.md** لخطوات النشر الكاملة (الفرونت اند على Netlify + الباك اند على Render).

## واجهة الـ API

جميع المسارات تحت `/api`، والجلسة تُحفظ عبر كوكي `httpOnly`.

- `POST /api/auth/register` — `{ name, email, password }`
- `POST /api/auth/login` — `{ email, password }`
- `POST /api/auth/logout`
- `GET  /api/auth/session` — يرجع بيانات المستخدم الحالي إن وُجدت جلسة
- `GET/PUT /api/progress/tasbeeh` — تقدم التسبيح والأذكار لليوم الحالي (محمي بالجلسة)
- `GET/PUT /api/progress/reading` — آخر سورة/آية تمت قراءتها (محمي بالجلسة)

## نقاط أمان مطبَّقة

- كلمات المرور مشفّرة بـ **bcrypt** (12 جولة salt)، لا تُخزَّن أبداً كنص واضح.
- جلسات `httpOnly` تمنع الوصول لكوكي الجلسة عبر JavaScript بالمتصفح.
- كل مسار يتعلق بتقدم المستخدم محمي بفحص جلسة فعلي من جهة الخادم (وليس فقط تحقق واجهة).
- التحقق من صحة المدخلات (طول كلمة المرور، صيغة البريد، تكرار البريد) يتم من جهة الخادم.

## قبل النشر الفعلي (Production)

- غيّر `SESSION_SECRET` بقيمة عشوائية طويلة.
- فعّل `NODE_ENV=production` (يفعّل خاصية `secure` بكوكي الجلسة، فيتطلب HTTPS).
- ضع الخادم خلف HTTPS فعلي (عبر Nginx أو خدمة الاستضافة).
- لأحمال استخدام أكبر، يمكن الانتقال من SQLite إلى PostgreSQL بسهولة (الكود يفصل منطق قاعدة البيانات بملف `db.js` واحد).
